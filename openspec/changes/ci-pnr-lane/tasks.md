(1) **Ref scoping**: GitHub Actions caches are isolated per ref, and `gh cache list` shows every cache this workflow ever wrote sitting in its own per-tag scope (`refs/heads/refs/tags/pnr-bringup-4`, `...-6`, `...-7`). Fixing this needs a decision, not just an edit: the key can be made deterministic (hash RTL *inputs* — `Bender.lock` + `hw/**` + the yosys scripts — instead of generated output), but the ref-scope half cannot be fixed by any key change while runs are tag-triggered; the options are to keep a VM-local netlist cache outside the git working tree (the runner workspace itself is wiped by `actions/checkout`'s clean), or to accept full resynthesis until this change merges and branch/dispatch triggers become usable. **Both halves fixed** (same day, after the user chose to do the cache work): the `actions/cache` step is replaced by a VM-local cache on the OS disk, mounted into the job container as `/synth-cache` via the container's `volumes:` entry (outside the workspace `actions/checkout` wipes; the OS disk, unlike `/mnt`, survives this lane's deallocate cycle, and Docker creates the host dir on first use so no VM provisioning step is needed). The key is a SHA-256 over `git rev-parse HEAD:<path>` tree hashes of `Bender.yml`, `Bender.lock`, `hw`, `target/ihp13/{yosys,pickle,pdk,src}`, `Makefile`, `iguana.mk`, `tools.mk`, plus the `yosys -V` string (the `:dev` image tag is mutable, so a rebuilt image with a different yosys must not reuse an old netlist). Git tree hashes are content-addressed, so submodule pins - notably the PDK liberty that ABC/DFFLIBMAP consume - are captured for free. **Validated retroactively**: the new key is byte-identical across `pnr-bringup-4`, `-6`, `-7`, `-8` and current HEAD, i.e. every one of those runs would have hit instead of re-paying ~3h (the first attempt at this check appeared to show the key still moving, which turned out to be zsh not word-splitting an unquoted variable in the *test script* - the real per-path comparison shows all ten paths identical across those tags). Cheap validation beyond actionlint: the three new step scripts were extracted from the YAML and run against a scratch cache in an `ubuntu:24.04` container (matching the job container's GNU `find -printf`/`mapfile` behaviour, which macOS lacks) - 14 assertions covering cold miss, save, warm hit with content verified, an interrupted save (no `.complete` marker) correctly treated as a miss, prune keeping the newest 5 without eating the current entry, and an unwritable cache dir degrading to a warning with exit 0. The key script was also run twice for determinism and once with a deliberately bogus path to confirm it fails loudly rather than silently contributing an empty field to the key (a hole found and closed during review - a failed `rev-parse` inside the original `printf` substitution would not have aborted the step).
