B. The idempotence bug this rehearsal caught
--------------------------------------------
Step 6 above reported "disabling apt-daily-upgrade.timer" on a host where step 3
had just shown the timer already disabled, i.e. the step was not idempotent and
re-ran systemctl on every convergence.

Cause: `systemctl is-enabled <unit>` prints the state AND exits non-zero when a
unit is disabled. The guard was

    "$(systemctl is-enabled apt-daily-upgrade.timer 2>/dev/null || echo disabled)"

so the non-zero exit fired the `|| echo disabled` as well, and the value became
the two-line string "disabled\ndisabled", which never equals "disabled".
Demonstrated locally:

    old expression -> disabled$'\n'disabled
    new expression -> disabled

Fixed by swallowing the exit code with `|| true` instead of appending a word,
and accepting disabled / masked / absent via a case statement.

Had this reached task 3.4 it would have run `systemctl disable --now` against the
live runner host on every convergence and failed that task's "every step already
satisfied, second invocation byte-for-byte identical" assertion.
